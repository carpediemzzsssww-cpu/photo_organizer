02 / 初始方案

技术先行的设计

基于对问题的理解,我快速设计了一个"功能完整"的解决方案。

功能设计

分层处理策略

设计了三层架构:

  • 即时层: 功能性文件识别(截图、验证码)
  • 短期层: 冗余照片检测与删除建议
  • 长期层: 智能分类与归档

  • HTML可视化报告生成

03 / 关键教训

过度设计的代价

在实际测试中,用户的一句质疑让我意识到方案存在根本性问题。

用户质疑: "AI怎么判断哪些截图可以删?"

当工具识别出截图并建议删除时,测试用户提出了一个核心问题:
"这些截图里可能有重要信息(银行转账、身份证、重要通知),如果AI误删了怎么办?你拿什么标准来判断哪些是临时的、哪些是重要的?"

这个问题暴露了产品设计的核心矛盾: 用户需要自动化,但更害怕误删重要数据。

❌

我犯的错误

  • 没有做用户调研,凭主观假设设计功能
  • 解决方案先行,而非问题驱动
  • 追求"技术炫技",堆砌AI能力
  • 功能过载,10+功能但没有聚焦核心价值
  • 忽视了信任问题:用户不敢让AI删照片
  • 跳过了原型验证,直接写了400行代码
✅

应该怎么做

  • 先访谈5-10个真实用户,验证痛点
  • 从用户最痛的点切入,而非"大而全"
  • 评估AI的真实价值:成本vs收益
  • 定义清晰的MVP:只做1个核心功能
  • 设计人机协作:AI辅助,人类决策
  • 先做低保真原型,找5个人测试反馈
04 / 深度反思

重新思考产品本质

这次失败让我系统性地反思了AI产品经理的核心能力要求。

AI PM ≠ 会用AI的PM

真正的AI产品经理需要具备的能力:

  • 判断什么问题适合用AI解决 - 不是所有问题都需要AI
  • 理解AI的能力边界 - 知道AI能做什么、不能做什么
  • 设计AI+人类的协作模式 - 而非完全自动化
  • 量化AI的价值 - 准确率提升?效率提升?成本是否合理?
  • 处理信任与安全问题 - 这往往是AI产品最大的挑战
# 正确的产品流程 1. 用户调研 访谈 5-10 个目标用户 - 你的相册有多少张照片? - 你多久整理一次?为什么不整理? - 你最困扰的是什么? - 你愿意让AI删除照片吗? 2. 需求验证 真实痛点 = "空间不足" or "找照片困难" or "整理麻烦"? 3. MVP定义 只做一个功能,做到极致 - 如果痛点是"空间不足" → 相似照片检测 - 如果痛点是"找照片" → 智能分类 4. 原型测试 Figma 画界面 → 找 5 个人测试 → 收集反馈 5. 如果验证通过,才开始写代码

关键洞察

🎯

问题定义>解决方案

花80%时间理解问题,20%时间做方案。好的产品从深刻理解用户痛点开始。

✂️

少即是多

MVP要克制,1个功能做到极致 > 10个功能都做得平庸。

🔬

快速验证假设

原型比代码更快。在投入大量开发前,先用低成本方式验证想法。

🤝

信任是AI产品的基石

用户不是害怕AI,而是害怕失去控制。设计人机协作,而非完全自动化。

05 / 最终成果

聚焦后的MVP

基于反思,我重新定义了产品范围,聚焦于最核心的价值。

重新定位

从"全自动"到"智能辅助"

新定位: 相似照片检测与智能推荐工具

核心价值:

  • 自动检测连拍照片组
  • AI评分推荐最佳照片
  • 用户确认后再删除(而非自动删除)
  • 可视化报告展示节省的空间
功能砍掉

暂缓的功能(V2.0再考虑)

  • ❌ 截图自动删除 → 改为"仅分类,不建议删除"
  • ❌ Live Photo处理 → 用户需求不明确,暂缓
  • ❌ 视频管理 → 范围过大,单独立项
  • ❌ 专业用户模式 → 先验证普通用户需求

核心学习

这个项目最大的价值不是做出了一个工具,而是让我深刻理解了:

好的产品经理不是功能的堆砌者,而是价值的聚焦者。

在AI时代,技术能力固然重要,但更重要的是:
✓ 识别真实问题的能力
✓ 设计人机协作的智慧
✓ 快速验证假设的执行力
✓ 克制功能的产品品味
